# Val-LLM 融合フレームワーク

[中文](README.md) | [English](README.en.md) | **日本語** | [Français](README.fr.md)

`valhalla-server` —— 任意の LLM を層の深さで分解し、Fate 体系で適合させ、
テキスト/音声/画像のモダリティを自由に融合し、重みへ焼き戻して
構造化セッションとして提供するフレームワーク。

## ポジショニング

Valhalla は **Fate ネイティブな長時程メモリ基盤**です。検索も生成も
しません。経験は受動的にブロック（バンドル）へ収束し、場強度
（エネルギー・√複雑度）で把持し、「回答／沈黙」の裁定は Fate 自身の
クラスタ方程式が行います。学習は判定の後、使用期間を通じて裁定者を
訓練します。提供するのは捏造ゼロ、沈黙の規律、振る舞いの定常性であり、
回答精度ではありません。チャットボット向けメモリ API でも、RAG の
代替でもなく、LoCoMo リーダーボードで競うものでもありません
（同一問題での比較と境界は
`docs/VALHALLA_COMPETITIVE_COMPARISON_20261113.md` を参照）。

## 仕組み

1. **分解** — LM を層深で四分（Q0→Hub、Q1→Tile、Q2→Stem、Q3→Hub）
   し、Fate で適合させます。
2. **融合** — 1 サンプルの文/声/図ポートを単一の Triad セッションで
   交錯パルスします。隔離も事前ルーティングもありません。
3. **記憶** — 信号は Fate の受動取り込み（`receive_passive`）で入り、
   収束がタイル/幹細胞を閉じ、素材は `(x−1)²` がブロック自身の方程式に
   適合するときバンドル化されます。
4. **裁定** — fog 判定（emit / abstain / defer）はエンジンの生きた
   Fate 方程式が行い、ゲートウェイは必ず実行します。Transformer
   デコードヘッドは Fate が放出した証拠の言い換えのみ可能で、棄権を
   覆すことはできません。
5. **焼き戻し** — 構造を基礎モデルへ書き戻して新しいチェックポイント
   を生成します（原モデルは不変）。モデルカードとハッシュ登録表付き。

  （旧エンジンと同期済み新エンジンで一致）。
- マルチモーダル ゲートウェイ（Fate-native アーム）：**6/9**、捏造 **0**。
- ローカル 312 ターン極限：コア針 **89/90**、捏造 **0/312**、
  攪乱質問への回答は 3/120（沈黙が既定）。

  356 行アームの取り込みは約 1.2 秒（段階的最適化で最重アーム

  記録（`docs/COMPREHENSIVE_SUMMARY_20261114.md` 参照）。

## リポジトリ構成

- `valhalla_server/` — ゲートウェイ（Fate 優先の裁定、デコードヘッド
  登録表、modelops パイプライン、VALENC1 引擎供給）。
- `engine/` — ValhallaBase/Fate 引擎の同期済み Rust ソース
  （正本は Valhalla ワークスペース。同期マニフェスト内蔵）。
- `docs/` — 実測サマリー、競合比較、ステータス報告。
- `tests/` — プローブと極限スイート。再現ドライバは
  `tests/reproduce_all.py`。
- `runtime/` — 静止時は暗号化（VALENC1）された引擎。
  `data/` — デコードヘッド登録表とモデル保管庫。

## 境界（明示します）

- RAG/Mem0 系との同一問題比較は、Valhalla が負ける項目を含めて
  文書化済みです。LoCoMo での勝利は主張しません。
- 能動的な発話（proactive emission）は主張しません。
- 現在の既知の失敗：虚偽前提の質問下では、命令形式の毒データを
  依然として出力する場合があります（実測済み。分析中であり、
  場当たり的な修正はしていません）。
