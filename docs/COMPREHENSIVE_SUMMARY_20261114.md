# Valhalla 全面总结（2026-11-14）：从优化到机制

本文是截至 2026-11-14 的总汇：原设计的形态、服务器时代的偏离、机制落地的
全过程、全部实测数字（含同日完成的本地版 312 轮极限测试）、以及最终裁定
——**当前系统的核心行为是机制（mechanism），不是优化（optimization）**，
这一字之差改变主张的类型、测试的含义与后续工作的性质。逐项证据在文中，
原始工件路径随附；未证明项单列，不与已测项混引。

## 0. 一页结论

1. **裁决权已归位**：问答的"答/沉默"只由 Fate 自己的收敛状态决定——抓取
   发生在块内竞争，裁决读取会话中活着的簇方程（`bundle_fits`）；位置、
   全局排名边距、词法轨道、transformer 改写均不参与裁决。产品路径
   （`hybrid.resolve_fate_answer`）只做呈现与出口纪律。
2. **三件套是形态变更，不是调参**：预学头部闭合进首块、动态卸载只带本
   tick 完成的瓦片、块内真竞争读数。三者修复前，"块"在部署形态下根本
   不存在（头部行不在任何块内、片段 id 跨追加碰撞、小语料全选）。
3. **机制判别通过**：无拟合常数（校准常数版已按裁定删除并 grep 核验）、
   阈值是系统自有学习状态（簇方程）、排列扰动下机制位置不变、312 轮长
   会话三段指标平直、失败全部可归因于先验已知的静止缺口、无规模涌现型
   失败。
4. **本地版极限（同日，引擎直连、无服务器代码）**：312 轮核心 90/90、
   编造 0、答案零漂移、零轮换。真极限是**摄入吞吐**（每轮延迟 0.5s→12s，
   会话 ~400 行时），属引擎 pulse 成本曲线，与网关/线缆无关（本地直连
   原样复现服务器版的 bulk 卡点）。
5. **诚实边界不变**：同题 LoCoMo-15 为 0/15（RAG 9/15、Mem0 5/15），不
   宣称赢；主动发声在本机未实现（n_eligible=0）；多跳、聚合各有天花板；
   Fate 簇方程在本机仍是"新生"状态（见 §5.3）。

## 1. 原设计：一链一币

所有者原始设计（`valhalla` 仓库 `docs/valhalla/` + fate-f64 源码为据）：

信号入 → Fate 被动摄入（`receive_passive`）→ 收敛关闭瓦片/词干 →
**集成束**（`bundle_fits(d0,d1)`：x=d0/d1，(x−1)² < 自有阈值）→ 场
（场强 = 能量·√复杂度）→ 刺激激活块 → **只按场强抓取** → `react` 只读
出口（沉默合法）→ **判后学**（反馈在裁决之后进入，每 10 信号判一次、
每 100 次判定才真调一次方程系数/阈值，阈值钳制 [0.01, 1.0]）。

关键语义（2026-11-03 所有者裁定）：`ClusterEquation` 初值 (1, −2, 1)，
即恰 (x−1)²；曾出现的"漂移根 ~0.45/2.13"被裁定为漂移、非原设计。

## 2. 服务器时代的偏离（优化层）与代价

服务器部署期叠加了一层服务器侧构造（代码在 `valhalla_server/hybrid.py`
等处，多数已停放、未删）：

| 构造 | 性质 | 实测代价 |
|---|---|---|
| hybrid 弱 emit（`resolve()`） | 优化（绕门） | 曾是注入攻击面（主报告 S11.7 记载）；现仅存对照臂，产品路径不调用 |
| 词法轨道 `tile_track`/`field_gate` | 优化（代裁） | 与 Fate 共享裁决权，违背"一链一币"；已停放 |
| 网关 cosine 抓取、BOOST spread 算子 | 文档/提案 | spread 在 BOOST 仓库只有一行文档，从未有运行时实现、从未移植 |
| 校准常数门（块相对边距 ≥0.15） | 优化（拟合） | 20 题零错边翻转——但阈值是人拟合的常数；已按所有者裁定**整体删除** |
| QA 中途正反馈 `apply_corpus_retrieval_feedback` | 负优化 | 自证式边距通胀的一个通道（重复问同一题边距 0.245→0.602→0.651）；主通道实为 follow-up 加成，已由优化 B 切断 |

服务器侧至今**仍在实跑**的只有会话形态层：`slim_session`/`link_session`、
动态卸载、fragment-only 会话形态（线缆 1–2.45MB、零轮换的来源）。

## 4. 优化 B/C（明确定性：是优化，不是机制）

| 项 | 内容 | 实测 |
|---|---|---|
| B | 与先前问题相同的问题不再算 follow-up：连续性加成只计**不同**先前问题 | 重复连问边距 0.245→0.602→0.651（改前）→ 恒定 0.245 ×10（改后）；20 题与 66 轮对话无回归 |
| C | 删 `decode_open` 中 `cidx<=1` 的 −0.18 位置惩罚（与头部闭合对冲） | 唯一变化 swap2 emit→弃权，按 harness 记分中性（其 must_not 为空）；伪前提沉默是纪律性收益 |

B/C 保留在代码中，但任何文档不得把它们记为机制功劳：它们清理的是
服务器时代评分堆栈的副作用，机制本身（§3）在没有 B/C 时也已成立
（见锚点 `20261114-fate-gate-anchor` 的对照数据）。

## 5. 机制判别：五条标准与证据

"机制"与"优化"的判别不靠自称，靠以下可核查项：

### 5.1 无拟合常数
当前放行路径上不存在任何为本题集拟合的阈值常数（grep 核验）。
唯一曾存在的拟合常数（相对边距 0.15）已按所有者裁定删除，并明文排除
在门锚点之外（`archive/20261114-fate-gate-anchor/BASELINE.md`）。

### 5.2 阈值是系统自有状态
门用的是会话簇方程 `bundle_fits`——方程系数与阈值由 `receive_passive`
→ `adapt` 的判后学节奏在运行时塑造。裁决质量因此继承方程的训练
状态，这正是机制与常数门的区别：常数门不会"没学过"，方程会。

### 5.3 法官未训练（如实标注）
三轮遥测一致：本机所有会话（引擎直连与网关）的簇方程均为新生状态
（系数 (1,−2,1)、阈值 0.01、适应 0–3 次）。QA 路径每会话只喂 10–30 个
被动信号，而一次真调整需约 1000 信号——**Fate 的方程在本机从未被
训练过**。扰动审计的直接后果：q2、swap1 的 (s1/s2−1)² 在 0.0078↔
0.0107–0.0138 间跨出生阈值摆动，布局敏感。这不是调参问题（无可调之
参），是训练状态问题；喂方程的通道恰被 §7 的吞吐墙挡住。

### 5.4 位置不变性
扰动审计（MM 逆序 / seed-99 洗牌 / 极端 seed 777）：q1 在三种布局均
正确 emit 且抓对块（块 [5,6]、[2,4]、[0,1]）；para/conflict/absent_attr/
q8 沉默保持。机制不依赖语料位置。

### 5.5 长程平直、无涌现失败
312 轮三段：核心 30/30、30/30、30/30；编造 0、0、0；陷阱（重评分）
12/20、12/20、12/20。所有失败在首段即已定性（毒丸复述、错属性绑定、
干扰题场读沉默），无一随规模新出现或恶化。

## 11. 为什么"机制"完全不一样

若是优化，正确的主张是"我们在本题集上调得更好"——换题集即失效，
失败要靠继续调。本次证据支持的是另一类主张：**"答与沉默由系统自有
的收敛状态裁决"这一形态本身，在排列扰动、三百轮长会话、零服务器
辅助下保持行为不变**。区别落在三处：

- **主张可证伪点不同**：机制主张的证伪点是形态（位置不变性、段平
  直、无拟合常数），已逐项测过；优化主张的证伪点是题集，未测即无。
- **失败的分类不同**：现存失败全部归入"法官未训练"（训练状态）、
  "绑定未落地"（缺一环形态）、"出口纪律未下沉"（层位）三类——都是
  结构坐标，没有一类是"参数没调好"。下一步工作是补形态与喂养，
  不是调参。
- **服务器层的地位不同**：对照证明服务器只剩出口纪律一件真实增
  量；产品叙事应从"网关+混合管线"改为"引擎即产品，网关是出口"。

后续（待所有者排序，本文不预设）：① 打通判后学的真实喂养通道
（先解摄入吞吐的增量性）；② 实体-属性绑定的形态落地；③ 出口纪律
是否下沉引擎；④ 方程受训后的边界案复测（届时扰动审计应全绿，
这是机制主张的下一个可证伪点）。

## 12. 定位重分析与复测（2026-11-15，所有者指令）

### 12.1 定位：描述变更

旧描述把 Valhalla 放在"给通用大模型加结构骨架"的位置——依附于
解码头、在记忆 API 的主场（LoCoMo 式长对话问答）与 Mem0/RAG 同
题竞分。这个定位与全部实测证据不符，现正式变更：

**Valhalla 是一个 Fate 原生的长时记忆基质（long-horizon memory
substrate）。它不检索、不生成：它把经历被动收敛成块，以自身簇
方程裁决"答与沉默"，判后学随使用时长持续训练裁决者本身。它销
售的不是答对率，是三件在长时运行下才显形的东西：零编造、沉默
纪律、行为平稳性。**

- **适用面**：试用/部署周期以周计、数据量注定超窗、编造代价高
  于沉默代价的场景（长周期试用正是所有者指出的常态："反正试用
  时长就好了"——自优化回路的慢增益由时长摊平，这不是缺陷而是
  定位的前提）。
- **明确不做**：不做聊天机器人的记忆 API（Mem0/Zep 的主场，不
  进场）；不做 RAG 替代（检索是它的对位面，不是它的形态）；
  不在 LoCoMo 式排行榜上宣称胜负（同题 0/15 如实保留）。
- **价值度量随之更换**：不用单题答对率，用长跑指标——312 轮编
  造 0、三段平直、核心答案零漂移、每题成本不随会话规模爆炸。
- 循环自优化审计（2026-11-15，只查未改）：四层均已实现（Fate
  内核判后 adapt、编排层 Fate 掌停、身体层 follow/promote、
  serve 层 QA 反馈闭环）；缺的是后台离线回路与问答侧的回路增
  益（每问个位数信号 vs 方程每 ~1000 信号动一次系数）。在新定
  位下这读作"随试用时长变准"的机制形态，而非待修 bug。

### 12.3 逐步优化第一步（2026-11-15 晚）：去重复 + 真碎片化

代码审计认定慢的主犯不是模型加载，而是三处全量重复：Fate 偏好
GPU 空算、Stem 物理场反复建销 cuBLAS 并全图重写、碎片闭合时近
全量导出。在原有结构上逐步修复，不重建：

1. **Fate 偏好去重复**（`fate-f64`）：Hub 反馈的方向向量恒为零，
   原 GPU coherence 对零向量逐个上 GPU 空转。现零向量直接走累
   加器回退；非零时也只在新增一整批信号后才可再算（Fate 天然
   触发，不随偏好读重复）；无新信号的 epoch 重标记不再写重复
   偏好快照（此前每个收敛周期重复 2–3 次）。
2. **Stem 物理场 Fate 触发**（`stem-cell`）：cuBLAS 加速器改为
   进程级常驻（失败记忆、不再重试）；物理场只在新细胞闭合或种
   群发生合并/分裂/死亡时重算，未变化的重复 evolve 直接跳过
   全图两两计算。
3. **真实碎片化一步**（`hub-f64`）：分段窗口原用 Hub Fate 时钟
   过滤 Tile 的 `completed_tick`（两套时钟速率不同，碎片实际装
   的是旧材料）。分段闭合现同时记录 Tile 自身时钟，导出优先按
   Tile 窗口取材，碎片开始真正只携带本段 tiles。
